# code-security

## 适用Agent
测试Agent

## 触发条件
测试Agent执行安全测试步骤时触发，或在代码开发完成后用户要求安全审计时触发。

## 执行步骤

| 序号 | 步骤 | 详细执行方式 |
|------|------|-------------|
| 1 | 读取代码 | 读取`output/code/`下最新代码文件列表，确定扫描范围 |
| 2 | OWASP Top 10检查 | 逐项检查OWASP Top 10安全风险，以表格列出：风险编号（SEC-NNN）、风险类别、是否存在、检查要点、检查结果、修复建议。具体检查项：A01-权限控制失效（越权/缺省配置）、A02-加密机制失效（敏感数据明文/弱算法）、A03-注入（SQL/命令注入/未参数化查询）、A04-不安全设计（业务逻辑漏洞/竞态条件）、A05-安全配置错误（默认密码/调试模式开启/不必要端口）、A06-易受攻击/过时组件（过期依赖/已知CVE）、A07-认证失败（弱密码策略/Session固定）、A08-软件/数据完整性失效（不安全反序列化/未验证更新）、A09-日志监控不足（安全事件未记录/无告警）、A10-服务器端请求伪造（SSRF/未校验外部URL） |
| 3 | 依赖安全扫描 | 检查项目依赖是否存在已知漏洞：Maven项目执行`./mvnw dependency-check:check`或`./mvnw org.owasp:dependency-check-maven:check`，前端项目执行`npm audit`，以表格列出：依赖名、版本、CVE编号、严重程度、修复版本 |
| 4 | 敏感信息泄露检查 | 扫描代码中是否包含硬编码敏感信息：密码/API Key/Secret/Token/私钥，搜索模式：`password=`, `secret=`, `api_key=`, `token=`, `BEGIN PRIVATE KEY`，以表格列出：文件路径、行号、泄露类型、修复建议（迁移至环境变量/配置中心） |
| 5 | CodeQL扫描建议 | 生成CodeQL集成建议：推荐在GitHub Actions中配置codeql.yml工作流，指定语言矩阵（java-kotlin/javascript-typescript），查询套件security-extended，构建模式autobuild，输出SARIF格式上传至Security tab |
| 6 | 安全修复建议 | 为每个发现的安全问题提供修复建议，包含：问题描述、风险等级（致命/高/中/低）、修复方案（含代码示例）、验证方法 |
| 7 | 生成安全报告 | 整合以上内容为安全检查报告，以Markdown格式写入`output/test/`目录，文件命名`security-report-{yyyy-MM-dd}.md` |

## 安全风险等级定义

| 等级 | 定义 | 示例 |
|------|------|------|
| 致命 | 可被远程利用，导致系统完全沦陷 | SQL注入、远程命令执行 |
| 高 | 可导致数据泄露或权限提升 | 认证绕过、越权访问 |
| 中 | 可能被利用但影响有限 | XSS、CSRF |
| 低 | 信息泄露或最佳实践违规 | 版本信息暴露、缺少安全头 |

## 输出规范

| 序号 | 规范项 | 要求 |
|------|--------|------|
| 1 | 格式 | Markdown |
| 2 | OWASP覆盖 | 必须逐项检查OWASP Top 10 |
| 3 | 修复建议 | 每个问题必须提供可执行的修复方案 |
| 4 | 风险等级 | 每个问题必须标注风险等级 |
| 5 | 依赖扫描 | 必须包含依赖漏洞扫描结果 |
