# 开发/设计文档输出 Skill

## 基本信息

| 属性 | 值 |
|------|-----|
| Skill名称 | design-doc-generation |
| 所属Agent | PM Agent |
| 用途 | 基于人类确认后的终态描述，反向输出设计文档和开发文档 |

## 核心理念

**从终点反推路径**：人类已确认应用终态，现在需要从终态描述中提取技术约束和设计决策，反向输出标准的架构设计文档、技术设计文档和开发规范文档。

## 触发条件

人类用户确认"应用终态描述"后，PM Agent调用本Skill输出设计文档。

## 前置依赖

- `result-first-definition` Skill已执行完成
- 人类用户已确认应用终态描述文档

## 执行步骤

### 步骤1：从终态描述中提取架构决策

阅读应用终态描述文档，提取以下架构信息：

1. **模块划分**：从后端服务概览中提取模块边界
2. **技术选型**：从项目概述中确定的技术栈推导架构风格
3. **部署方案**：从非功能性终态推导部署架构
4. **交叉关注点**：从业务规则中提取横切关注点（日志、认证、授权等）

### 步骤2：输出架构设计文档

基于步骤1提取的信息，产出架构设计文档，存放至`agent-doc/architecture/`。

文档结构：

```
# [项目名称] - 架构设计文档

## 1. 架构风格与选型
- 架构风格（单体/微服务/Serverless等）
- 技术栈选型及理由
- 架构决策记录(ADR)

## 2. 模块划分
- 模块列表与职责
- 模块间依赖关系（Mermaid图）
- 模块间通信方式

## 3. 部署架构
- 部署拓扑图
- 环境规划（开发/测试/生产）
- 高可用与扩展性方案

## 4. 交叉关注点
- 认证与授权方案
- 日志与监控方案
- 错误处理策略
- 缓存策略
```

### 步骤3：从终态描述中提取技术设计决策

阅读应用终态描述文档，提取以下技术信息：

1. **数据模型**：从数据层终态中的表设计推导ER模型
2. **接口定义**：从API完整列表推导OpenAPI规范
3. **组件选型**：从前端终态推导UI组件需求
4. **集成方案**：从处理链路推导服务集成方式

### 步骤4：输出技术设计文档

基于步骤3提取的信息，产出技术设计文档，存放至`agent-doc/technical-design/`。

文档结构：

```
# [项目名称] - 技术设计文档

## 1. 数据模型
- ER图
- 表结构定义（字段、类型、约束、索引）
- 数据迁移策略

## 2. 接口定义
- API规范（路径、方法、请求/响应Schema）
- 接口与前端操作映射表
- 错误码定义

## 3. 组件设计
- 前端组件树
- 后端服务组件
- 共享组件

## 4. 集成方案
- 服务间调用方式
- 外部系统集成点
- 数据同步策略

## 5. 验收标准
- Given-When-Then格式的验收条件
```

### 步骤5：输出开发规范文档

基于终态描述和设计文档，产出开发规范文档，存放至`agent-doc/dev-plan/`。

文档结构：

```
# [项目名称] - 开发规范文档

## 1. 项目结构规范
- 目录结构约定
- 命名规范（文件、类、方法、变量）
- 代码风格要求

## 2. 开发环境
- 本地开发环境搭建指南
- 依赖管理
- 构建与运行

## 3. 编码规范
- 前端编码规范
- 后端编码规范
- 数据库操作规范

## 4. Git规范
- 分支策略
- 提交消息规范
- Code Review流程

## 5. 测试规范
- 测试覆盖率要求
- 测试类型与层级
- 测试命名规范
```

## 输入

| 序号 | 输入项 | 来源 |
|------|--------|------|
| 1 | 应用终态描述文档 | `agent-doc/result-first/result-definition.md` |
| 2 | 人类确认信息 | 人类用户 |

## 输出

| 序号 | 输出项 | 存放位置 |
|------|--------|----------|
| 1 | 架构设计文档 | `agent-doc/architecture/architecture-design.md` |
| 2 | 技术设计文档 | `agent-doc/technical-design/technical-design.md` |
| 3 | 开发规范文档 | `agent-doc/dev-plan/dev-standards.md` |

## 注意事项

1. 设计文档是从终态反推出来的，必须确保每一条设计决策都能对应到终态描述中的某一项
2. 如果终态描述中存在矛盾（如前端需要某接口但后终态未定义），需标注并返回PM Agent决策
3. 架构设计文档必须包含ADR（Architecture Decision Record），记录关键决策的理由
4. 技术设计文档的API定义必须与终态描述中的API列表完全对应
