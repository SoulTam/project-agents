# technical-spike

## 适用Agent
PM Agent

## 触发条件
用户提出技术调研需求时触发，或在开发计划中识别到需要先行调研的关键技术决策时触发。

## 执行步骤

| 序号 | 步骤 | 详细执行方式 |
|------|------|-------------|
| 1 | 定义调研目标 | 明确调研问题：需要解决的核心技术问题是什么？为什么这个问题阻塞了开发？调研时间盒是多少？决策截止日期是什么？ |
| 2 | 列出调研问题 | 分解为1个主要问题和若干次要问题，主要问题必须具体可回答，次要问题覆盖相关方面 |
| 3 | 制定调研计划 | 列出具体调研任务清单：搜索现有文档、分析代码库模式、研究外部资源（API/库/示例）、创建概念验证原型、文档化发现和建议 |
| 4 | 定义成功标准 | 明确调研完成的判定条件：每个标准必须可验证 |
| 5 | 描述技术上下文 | 列出关联的系统组件、依赖的其他调研或决策、已知约束 |
| 6 | 执行调研 | 按计划执行：Phase 1 信息收集（搜索文档/分析代码/研究外部资源）→ Phase 2 验证测试（创建原型/运行实验/记录结果）→ Phase 3 决策文档化（综合发现/输出建议/创建后续任务） |
| 7 | 记录调研发现 | 文档化调研结果：调查结果、原型测试笔记、外部资源链接 |
| 8 | 输出决策建议 | 给出明确的技术建议：推荐方案、选择理由（相对替代方案）、实施注意事项、后续行动清单 |
| 9 | 生成Spike文档 | 按标准化模板生成技术调研文档，写入`agent-doc/spike/`目录，命名`{category}-{short-description}-spike.md` |

## 输出规范

| 序号 | 规范项 | 要求 |
|------|--------|------|
| 1 | 格式 | Markdown + front matter |
| 2 | 时间盒 | 必须定义明确的调研时间限制 |
| 3 | 成功标准 | 必须定义可验证的完成标准 |
| 4 | 决策 | 必须输出明确的技术建议 |
| 5 | 一问一Spike | 每个Spike只聚焦一个技术决策 |
