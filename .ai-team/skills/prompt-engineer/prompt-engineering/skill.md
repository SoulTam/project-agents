# 提示词工程 Skill

## 概述
对用户原始请求进行系统化增强，使下游Agent能更精准、高效地理解和执行任务。

## 适用场景

| 序号 | 场景 | 示例 |
|------|------|------|
| 1 | 请求表述模糊 | "帮我做个登录" → 补充：什么登录方式？需要哪些字段？ |
| 2 | 缺少上下文 | "修改那个接口" → 补充：哪个接口？当前接口定义是什么？ |
| 3 | 隐含约束未说明 | "加个搜索功能" → 补充：搜索引擎选型？分页策略？性能要求？ |
| 4 | 请求过于笼统 | "优化系统" → 拆解：哪方面优化？性能？安全？可维护性？ |
| 5 | 多意图混合 | "做个用户管理加上权限和导出" → 拆解为独立子请求 |

## 执行步骤

### Step 1: 意图识别
1. 分析用户请求，识别请求类型：
   - **需求型**：新增功能/模块
   - **修改型**：修改已有功能/修复Bug
   - **咨询型**：技术方案/架构建议
   - **调试型**：问题排查/错误修复
   - **优化型**：性能/安全/代码质量改进
2. 提取核心意图，用一句话概括用户真正想要什么
3. 识别涉及的技术领域（前端/后端/架构/测试/DevOps/全栈）

### Step 2: 消歧与澄清
1. 检测模糊表述，逐项列出歧义点
2. 根据项目上下文推断最可能的含义
3. 无法推断时，在增强提示词中标注 `[待确认：xxx]`
4. 消歧规则：
   - "那个" → 查找最近上下文中的指代对象
   - "类似xx" → 查找项目中的参照实现
   - "尽快/尽快完成" → 转化为具体优先级（P0/P1/P2）
   - "合适的方式" → 根据技术栈和项目规范推荐具体方案

### Step 3: 上下文注入
1. 扫描 `agent-doc/` 目录，了解项目当前状态和已有产出
2. 查询 `.ai-team/knowledge-base/` 中相关知识：
   - 项目领域知识（`domain/domain-knowledge.md`）
   - API策略（`api-strategies/`）
   - 设计模式（`patterns/`）
   - 历史决策（`decisions/`）
3. 识别与请求相关的已有代码/文档/架构
4. 将关键上下文摘要注入增强提示词

### Step 4: 约束补充
1. 自动附加项目级约束：
   - 技术约束：从 `.cursorrules` 和 `global-rules.md` 提取
   - 质量约束：代码规范、测试要求、文档要求
   - 安全约束：OWASP、敏感信息保护、安全扫描
2. 根据请求类型追加特定约束：
   - 需求型 → 需求分析模板、验收标准
   - 修改型 → 影响范围分析、回归测试
   - 调试型 → 日志规范、错误信息格式
   - 优化型 → 基准指标、优化目标

### Step 5: 结构化重构
1. 将增强后的信息按模板结构化输出
2. 确保每个字段都有明确内容，不留空白
3. 多意图请求拆解为独立子请求，标注优先级和依赖关系
4. 在增强提示词中明确要求：下游所有Agent执行完后，必须在对话总结中输出Agent责任记录表（格式：| Agent名称 | 执行内容摘要 | 关联Skill |）

### Step 6: 展示与确认传递
1. 在对话中直接展示增强后的结构化提示词给用户
2. 等待用户确认：
   - 用户确认 → 将增强后的提示词传递给PM Agent
   - 用户要求修改 → 根据用户反馈调整提示词，重新展示确认
3. 确认后直接传递给PM Agent，不输出到文档

## 增强策略矩阵

| 请求类型 | 必须增强项 | 可选增强项 |
|----------|-----------|-----------|
| 需求型 | 功能范围、验收标准、技术栈 | 性能指标、用户量级 |
| 修改型 | 影响范围、回归点、当前实现 | 修改原因、替代方案 |
| 咨询型 | 技术选项对比、项目约束 | 成本分析、风险评估 |
| 调试型 | 错误信息、复现步骤、环境 | 日志片段、近期变更 |
| 优化型 | 当前指标、优化目标、约束 | 投入产出比、渐进方案 |

## 质量检查

增强后的提示词必须满足：

| 序号 | 检查项 | 标准 |
|------|--------|------|
| 1 | 完整性 | 所有模板字段均有内容 |
| 2 | 无歧义 | 无未消解的模糊表述（待确认项除外） |
| 3 | 可执行 | 下游Agent无需二次澄清即可开始工作 |
| 4 | 有上下文 | 包含项目当前状态和相关已有产出 |
| 5 | 有约束 | 包含技术/质量/安全约束 |
