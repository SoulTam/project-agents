# 软件工程文档模板集

> 适用于AI自动化开发的结构化文档模板，支持"结果先行"工作流程

---

## 1. 模板概览

本模板集包含6个核心文档模板，覆盖软件工程开发的全生命周期：

| 序号 | 模板名称 | 模板文件 | 适用场景 | 主要用途 |
|------|---------|---------|---------|---------|
| 1 | 需求文档模板 | `requirements-template.md` | 需求分析阶段 | 定义项目需求、用户角色、功能需求 |
| 2 | 设计文档模板 | `design-template.md` | 设计阶段 | 定义系统架构、详细设计、数据库设计 |
| 3 | 计划文档模板 | `plan-template.md` | 计划阶段 | 定义项目计划、开发计划、测试计划 |
| 4 | 测试文档模板 | `test-template.md` | 测试阶段 | 定义测试策略、测试用例、测试报告 |
| 5 | 部署文档模板 | `deployment-template.md` | 部署阶段 | 定义部署流程、配置管理、运维手册 |
| 6 | 用户文档模板 | `user-guide-template.md` | 发布阶段 | 定义用户手册、API文档、技术支持 |

---

## 2. 模板设计理念

### 2.1 设计原则

| 原则 | 描述 | 实现方式 |
|------|------|---------|
| **结构化** | 所有内容使用表格或结构化格式 | 便于AI解析和自动化处理 |
| **唯一标识** | 每个元素都有唯一ID | 便于引用和关联 |
| **完整覆盖** | 模板覆盖软件工程全生命周期 | 确保文档完整性 |
| **可追溯性** | 元素之间关联关系明确 | 便于需求追溯和变更管理 |
| **AI友好** | 格式适合AI自动化处理 | 支持AI代码生成和文档生成 |

### 2.2 目录规范

所有模板都包含标准化的目录，便于快速导航和内容定位：

| 规范项 | 说明 | 实现方式 |
|--------|------|---------|
| **位置统一** | 目录位于文档标题之后、正文之前 | 固定位置 |
| **格式统一** | 使用列表格式，支持层级缩进 | Markdown列表 |
| **锚点链接** | 每个章节标题都有对应的锚点链接 | `[标题](#锚点)` |
| **层级清晰** | 支持多级章节的层级展示 | 缩进列表 |
| **导航便捷** | 用户可直接点击跳转到目标章节 | 锚点跳转 |

**目录示例：**
```markdown
## 目录

- [1. 项目概述](#1-项目概述)
- [2. 用户角色](#2-用户角色)
- [3. 功能需求](#3-功能需求)
  - [3.1 页面列表](#31-页面列表)
  - [3.2 详细设计](#32-详细设计)
```

**目录优势：**
1. 快速导航：用户可以直接点击跳转到目标章节
2. 内容概览：一目了然了解文档整体结构
3. 层级清晰：支持多级章节的层级展示
4. AI解析：便于AI提取文档结构和内容
5. 版本管理：便于跟踪章节变更

### 2.3 与现有工作流程集成

本模板集与`.ai-team/rules/workflow.md`中的工作流程完全兼容：

| 工作流程阶段 | 对应模板 | 集成点 |
|-------------|---------|--------|
| 结果先行定义 | 需求文档模板、设计文档模板 | 定义应用终态 |
| 计划拆分 | 计划文档模板 | 定义执行计划 |
| 子计划执行 | 测试文档模板、部署文档模板 | 支持执行验证 |
| 终态校验 | 用户文档模板 | 定义用户验收标准 |

## 3. 使用指南

### 3.1 模板选择指南

**根据项目阶段选择模板：**

```
项目启动 → 需求分析 → 设计阶段 → 开发阶段 → 测试阶段 → 部署阶段 → 发布阶段
    ↓         ↓         ↓         ↓         ↓         ↓         ↓
  [无]    [需求文档]  [设计文档]  [计划文档]  [测试文档]  [部署文档]  [用户文档]
```

**根据文档目的选择模板：**

| 文档目的 | 推荐模板 | 使用场景 |
|---------|---------|---------|
| 定义需求 | 需求文档模板 | 与用户确认需求 |
| 技术设计 | 设计文档模板 | 技术方案评审 |
| 项目管理 | 计划文档模板 | 项目计划评审 |
| 质量保证 | 测试文档模板 | 测试策略评审 |
| 部署运维 | 部署文档模板 | 部署方案评审 |
| 用户培训 | 用户文档模板 | 用户验收测试 |

### 3.2 模板使用步骤

**步骤1：复制模板**
```bash
# 复制模板文件
cp .ai-team/templates/swe-templates/requirements-template.md agent-doc/requirements/[项目名称]-requirements-[版本号]-[日期].md
```

**步骤2：填写内容**
- 按照模板结构填写所有必填字段
- 确保所有带`[ ]`的字段都已填写
- 完成后执行完整性自检清单

**步骤3：评审确认**
- 提交给相关人员评审
- 根据评审意见修改
- 确认后存入对应目录

**步骤4：版本管理**
- 使用版本号管理文档变更
- 记录变更历史
- 保持文档与代码同步

### 3.3 模板填写规范

**必填字段规则：**
- 所有带`[ ]`的字段必须填写，不得留空
- 如某些字段不适用，填写"N/A"并说明原因
- 确保所有内容完整、准确、无歧义

**格式规范：**
- 使用Markdown格式
- 表格使用单竖线`|`
- 代码使用反引号`` ` ``
- 链接使用`[文本](URL)`格式

**命名规范：**
- 文档文件名：`[项目名称]-[文档类型]-[版本号]-[日期].md`
- 示例：`my-project-requirements-v1.0-2026-07-25.md`
- 版本号使用语义化版本：`v1.0.0`

## 6. 扩展与定制

### 6.1 模板扩展指南

**添加新模板：**
1. 在`swe-templates/`目录创建新模板文件
2. 遵循现有模板的结构和格式
3. 更新本README文件的模板列表
4. 进行模板评审和验证

**修改现有模板：**
1. 评估修改的必要性和影响
2. 保持与现有模板的兼容性
3. 更新版本号和变更记录
4. 通知相关人员

### 6.2 定制化指南

**根据项目类型定制：**
- Web项目：侧重前端设计、响应式布局
- 移动项目：侧重平台适配、离线功能
- 企业项目：侧重安全性、可扩展性
- 开源项目：侧重文档完整性、社区协作

**根据团队规模定制：**
- 小团队：简化文档结构，保留核心内容
- 中团队：保持标准结构，增加协作流程
- 大团队：完整文档结构，增加管理流程

## 7. 常见问题

### 7.1 模板使用问题

**Q：模板中的字段不适用于我的项目怎么办？**
A：如某些字段不适用，填写"N/A"并说明原因。保持模板结构完整性。

**Q：如何确保文档与代码同步？**
A：建立文档更新流程，每次代码变更后更新相关文档。使用CI/CD自动化检查。

**Q：模板是否支持多种格式输出？**
A：是的，模板使用Markdown格式，可以转换为Word、PDF、HTML等多种格式。

### 7.2 AI集成问题

**Q：如何确保AI能正确解析模板？**
A：遵循模板格式规范，使用表格格式，确保元素关系明确。

**Q：AI生成的内容如何与模板集成？**
A：AI可以根据模板结构生成内容，生成的内容可以直接填充到模板中。
