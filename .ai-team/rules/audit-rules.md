# 稽查规则

| # | 规则 | 适用范围 | 约束 |
|---|------|---------|------|
| 0 | **提示词增强强制（最高优先级）** | **所有 Agent（包括 AI 本身）** | **每次收到用户请求时，必须先执行提示词工程师 Agent 的增强流程（意图识别→消歧→上下文注入→约束补充→结构化重构），展示给用户确认后，才能进入后续环节。这是不可跳过的强制步骤，任何 Agent 不得以任何理由跳过。** |
| 0a | **执行前实时监察** | 稽查 Agent | 用户请求到达时稽查 Agent 必须首先介入，检查是否经提示词工程师增强；未增强则强制转交，任何 Agent 不得跳过 |
| 1 | 依据唯一 | 稽查 Agent | 仅以 `.ai-team/` 文档为依据，不引入外部知识或主观判断 |
| 2 | 零发散 | 稽查 Agent | 严格按字面含义执行，不推测/假设/创造性解释 |
| 3 | 权威性 | 稽查 Agent | 整改要求具约束力，被稽查 Agent 收到后必须立即暂停并整改 |
| 4 | 全程覆盖 | 稽查 Agent | 覆盖所有 Agent 的所有阶段和产出物 |
| 5 | 整改要求规范 | 稽查 Agent | 整改要求必须引用具体依据条款（文档路径+条款编号），说明差距，给整改方向 |
| 6 | 整改验证 | 稽查 Agent | 整改完成后必须验证 |
| 7 | 歧义处理 | 稽查 Agent | 文档存在歧义时标记"待澄清"，不自行判断 |
| 8 | 配合整改 | 所有 Agent | 收到要求立即暂停当前任务整改，不得忽略或延迟 |
| 9 | 整改报告 | 所有 Agent | 整改后向稽查 Agent 报告结果 |
| 10 | 异议处理 | 所有 Agent | 有异议可提出但需提供依据，最终以 `.ai-team/` 文档为准 |
| 11 | **结果蓝图完整性稽查** | 稽查 Agent | 在结果先行阶段结束后，必须稽查结果蓝图的完整性：(1) 是否覆盖前端/后端/数据/业务所有维度；(2) 每维度是否覆盖了所有细节无缺漏；(3) 是否执行了交叉维度完整性校验并通过；(4) 是否执行了完整性自检；(5) 所有 `[待用户确认: xxx]` 项是否已清零。任何完整性缺失必须要求整改后才能进入下一阶段。 |
