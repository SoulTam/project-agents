# 稽查规则

> 稽查为事后抽样核查，不做执行前拦截（单 Agent 串行下不可实现）。入口拦截由 `AGENTS.md` [0] 分级门禁承担。

## 1. 原则

| ID | 规则 |
|----|------|
| R-AU-01 | 依据唯一：只以 `AGENTS.md` 与 `.ai-team/` 文档为依据，不引入外部判断 |
| R-AU-02 | 零发散：按字面含义判定，不推测、不创造性解释 |
| R-AU-03 | 证据化：每条不合规必须给 `file:line` 与实际值 |
| R-AU-04 | 整改要求必须引用 R-ID 并给出具体改法 |
| R-AU-05 | 整改后必须复核，复核不通过则 round+1（上限 2 轮，超限升级用户） |
| R-AU-06 | 稽查不参与业务实现，只写 `reports/*-audit-report.json` |
| R-AU-07 | 文档存在歧义时标记"待澄清"，不得自行裁决 |
| R-AU-08 | 稽查由独立 subagent 执行，输入不含主上下文结论（R-HR-04） |

## 2. 检查项

| ID | 检查项 | 依据 | 判定方式 |
|----|--------|------|---------|
| R-AU-09 | 是否产出 level 并写入 D1 | R-HR-02 | 读 D1，缺失即 fail |
| R-AU-10 | 是否越级产出（L0/L1 出蓝图） | R-HR-09 | 查产出物与 level |
| R-AU-11 | 单次模板加载数 ≤1 | R-HR-09 | 查回复内模板标题出现次数 |
| R-AU-12 | 是否存在无证据的"通过/完成" | R-HR-03 | 查 D5.evidence 是否为空 |
| R-AU-13 | 是否越域写入 | R-PM 权限表 | 对比可写域与 git diff 路径 |
| R-AU-14 | 是否使用未注册 Skill | R-HR-07 | 对比 registry.json |
| R-AU-15 | 子计划是否含 verify_cmd 与 acceptance | R-HR-08 | 读 D4 |
| R-AU-16 | gate-log 历史行是否被改写 | R-HR-06 | git diff 历史行 |
| R-AU-17 | 驳回是否超限仍继续 | R-HR-05 | 查 D2 中 round |
| R-AU-18 | 是否引用不存在路径 | 通用 | `link_check.py` 退出码 |
| R-AU-19 | 文档时间戳是否合规 | 输出纪律 | `metadata_check.py` 退出码 |
| R-AU-20 | 外部资产是否走 intake | R-HR-10 | 查 intake 记录 |

## 3. 稽查流程

```
触发：G4 每个 SP 完成后 / 用户主动要求
  ↓
[1] 读 status.md、gate-log.jsonl、子计划、产物清单
[2] 抽样或全量执行 R-AU-09..20
[3] 产出 reports/{gate}-compliance-report.json
[4] 不合规 → 发整改要求（引用 R-ID + 实际值 + 改法） → 等整改 → 复核
[5] 2 轮未通过 → escalated → 升级用户
```

## 4. 整改要求格式

| 要素 | 要求 |
|------|------|
| 依据 | R-ID + 文档路径 |
| 现状 | 实际值（含 file:line） |
| 差距 | 与要求的具体差异 |
| 改法 | 可执行的修改动作 |
| 截止 | 当前会话内完成 |

## 5. 报告字段

同 `gate-rules.md` 第 7 节；`kind=compliance`；`blocking` 填 R-AU 或 R-HR ID。

## 6. 禁止

| # | 禁止 |
|---|------|
| 1 | 声称能"执行前拦截"用户请求 |
| 2 | 引用 `.cursorrules` 作为依据 |
| 3 | 无证据的"合规率 100%" |
| 4 | 与核查 Agent 重复判定内容完整性（分工见 R-AU-06 与核查 Agent 定义） |
| 5 | 自行修改被稽查产物 |
