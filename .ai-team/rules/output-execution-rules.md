# 输出与执行规则

> 涵盖：输出规则、执行规则、提示词工程规则

---

## 1. 输出规则

| # | 规则 | 适用范围 | 约束 |
|---|------|---------|------|
| 1 | 禁止思考过程 | 所有 Agent | 输出中不展示推理、内心独白 |
| 2 | 禁止假设性内容 | 所有 Agent | 不输出假设性问题、建议、非必须的推荐 |
| 3 | 简洁原则 | 所有 Agent | 删除某句不影响理解则不输出 |
| 4 | 默认 Markdown | 所有 Agent | 文档默认 Markdown 格式 |
| 5 | 结构化 | 所有 Agent | 表格优先，子项用阿拉伯数字标注 |
| 6 | 目录结构 | 所有 Agent | 树状图输出 |
| 7 | 关系图 | 所有 Agent | Mermaid 语法 |
| 8 | Agent 责任记录 | 所有 Agent | 每次请求结束输出表格：\| Agent名称 \| 执行内容摘要 \| 关联Skill \| |
| 9 | 表格格式 | 所有 Agent | 单竖线 `\|` 分隔列，禁止双竖线 `\|\|` |

---

## 2. 执行规则

| # | 规则 | 适用范围 | 约束 |
|---|------|---------|------|
| 1 | 计划前置 | 所有 Agent | 任务性请求先在 `agent-doc/plan/` 输出计划，经用户确认后执行 |
| 2 | 计划命名 | 所有 Agent | `yyyy-MM-dd + 序号 + 简要描述` |
| 3 | 计划粒度 | 所有 Agent | 每步骤写明详细执行方式，禁止概括语言 |
| 4 | 文件分类 | 所有 Agent | 同一目录不放多个类型文件 |
| 5 | 用户请求记录 | PM Agent | 请求超过两句话时，记录到 `agent-doc/user-request/`，一份一次 |
| 6 | 路径约定 | 所有 Agent | 配置基于 `.ai-team/`，产出物基于 `agent-doc/` |
| 7 | 跨项目迁移 | PM Agent | 首次进入新项目确认 `.ai-team/` 目录结构 |
| 8 | 计划执行校验 | 所有 Agent | 每步执行后比对实际 vs 计划：一致则更新细节；不一致则列差异并暂停询问 |
| 9 | **结果蓝图完整性保障** | PM Agent | 结果蓝图必须覆盖整个应用的全部细节，不能仅有核心或重点信息。PM Agent在提交确认前必须执行完整性自检（15项检查）和交叉维度完整性校验（前端-后端-数据-业务全链路校验），确保无缺漏、无维度间不一致。信息不完整时须用 `[待用户确认: xxx]` 标注并向用户提问，所有待确认项清零后才能进入下一步。 |
| 10 | **模板内容强制文件落地** | 所有 Agent | 每个模板填充完毕后，必须将完整内容同时保存到 `.opencode/instructions.md` 中各模板后标注的对应文件路径。聊天窗口展示仅作为交互展示，文件落地才是正式产出。不得仅输出在聊天窗口而不保存文件。文件保存动作不可省略。 |
| 11 | **独立子计划文件** | PM Agent | 每个子计划必须是独立文件（`agent-doc/plan/[确认日期]/SP-XX-xxx.md`），不得合并。子计划中的"最终结果"和"验收标准"必须从结果蓝图中**逐字逐句完整拷贝**对应章节的全部内容，不得做任何修改、删减、概括或重述。蓝图原文即子计划的结果定义，执行Agent打开子计划文件即可看到完整的终态目标。不得在子计划中留下"参考结果蓝图"等需要Agent自行判断的模糊指示。仅当发现蓝图章节间存在冲突时，可暂停向用户提问 |
| 12 | **执行步骤三要素** | PM Agent | 子计划中每个执行步骤必须包含三个要素：(1)**做什么**——一句话描述目标；(2)**怎么做**——具体工具、命令、函数、操作流程；(3)**正反约束**——必须做的规则和禁止做的行为。代码开发类子计划（类型B/C/D）三要素必须完整；纯文档类子计划（类型A）"怎么做"可简化但正反约束不可省略。执行Agent按步骤中的"怎么做"和"正反约束"执行，不得自行发挥 |

## 3. 提示词工程规则

| # | 规则 | 约束 |
|---|------|------|
| 1 | **请求预处理（不可跳过）** | **所有用户请求必须先经提示词工程师 Agent 增强（意图识别→消歧→上下文注入→约束补充→结构化重构→用户确认），增强并确认后才能进入后续环节。这是最高优先级的强制规则。** |
| 2 | 意图识别 | 识别请求类型（需求/修改/咨询/调试/优化）并标注核心意图 |
| 3 | 消歧澄清 | 检测模糊表述并消歧，无法推断时标注 `[待确认：xxx]` |
| 4 | 上下文注入 | 从知识库和 `agent-doc/` 检索相关信息注入提示词 |
| 5 | 增强确认 | 增强后的提示词在对话中展示给用户确认，不输出到文档 |
