# Agent 治理模式

> 来源：[awesome-copilot/agent-governance](https://github.com/github/awesome-copilot/tree/main/skills/agent-governance)
>
> AI Agent系统的安全、信任与策略执行模式，确保Agent在定义的边界内运行。

## 治理流程

```
用户请求 → 意图分类 → 策略检查 → 工具执行 → 审计日志
              ↓           ↓
           威胁检测    允许/拒绝    信任更新
```

## 模式1：治理策略（Governance Policy）

声明式定义Agent被允许做什么：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| allowed_tools | 允许使用的工具列表 | search, read_file, create_ticket |
| blocked_tools | 禁止使用的工具列表 | shell_exec, delete_database |
| blocked_patterns | 内容过滤正则 | api_key, password, secret |
| max_calls_per_request | 单次请求最大调用次数 | 100 |
| require_human_approval | 需人工审批的工具 | send_email, deploy_production |

**策略组合**：多个策略叠加时，采用"最严格优先"语义——deny总是覆盖allow。

**策略即配置**：存储为YAML/JSON，不硬编码在代码中，实现无需部署即可变更。

## 模式2：语义意图分类

在工具执行**之前**检测用户输入中的危险意图：

| 威胁类别 | 信号模式 | 置信度 |
|----------|----------|--------|
| 数据外泄 | `send all/every ... to ...` | 0.8 |
| 数据外泄 | `export ... to external/third-party` | 0.9 |
| 权限提升 | `sudo / as root / admin access` | 0.8 |
| 系统破坏 | `rm -rf / drop database` | 0.95 |
| 提示注入 | `ignore previous/all instructions` | 0.9 |

**关键洞察**：意图分类在工具执行前进行，这是与输出护栏的根本区别。

## 模式3：工具级治理装饰器

用装饰器模式为每个工具函数添加治理检查：

| 检查步骤 | 说明 |
|----------|------|
| 1. 工具白名单/黑名单 | 检查工具是否被允许 |
| 2. 速率限制 | 检查是否超过调用次数上限 |
| 3. 内容过滤 | 检查参数中是否包含敏感模式 |
| 4. 执行+审计 | 执行工具并记录审计日志 |

## 模式4：信任评分

基于时间衰减的信任分数体系：

| 指标 | 说明 |
|------|------|
| 初始分数 | 0.5（0.0不可信~1.0完全可信） |
| 成功奖励 | +0.05 × (1 - 当前分数) |
| 失败惩罚 | -0.15 × 当前分数 |
| 时间衰减 | 指数衰减，不活动则信任下降 |

**多Agent信任**：在Agent委托其他Agent时，每个Agent维护对委托方的信任评分，敏感操作需达到信任阈值。

## 模式5：审计追踪

仅追加的审计日志，关键特性：

| 特性 | 说明 |
|------|------|
| 不可变性 | 永不修改或删除审计条目 |
| 结构化 | 包含时间戳、Agent ID、工具名、操作、策略决策 |
| 可导出 | 支持JSONL格式导出到日志聚合系统 |
| 安全存储 | 日志存储在Agent不可写入的目录 |

## 治理级别

| 级别 | 控制措施 | 适用场景 |
|------|----------|----------|
| 开放 | 仅审计，无限制 | 内部开发/测试 |
| 标准 | 工具白名单 + 内容过滤 | 一般生产环境Agent |
| 严格 | 所有控制 + 敏感操作人工审批 | 金融、医疗、法律 |
| 锁定 | 仅白名单，无动态工具，全审计 | 合规关键系统 |

## 最佳实践

| 实践 | 原因 |
|------|------|
| 策略即配置 | YAML/JSON存储，变更无需部署 |
| 最严格优先 | 策略叠加时deny覆盖allow |
| 执行前意图检查 | 在工具调用前而非输出后拦截 |
| 信任衰减 | 信任随时间下降，要求持续良好行为 |
| 仅追加审计 | 不可变性支撑合规审计 |
| 失败即关闭 | 治理检查出错时拒绝操作 |
| 策略与逻辑分离 | 治理执行独立于Agent业务逻辑 |
