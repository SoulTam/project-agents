# IBM i文档规范 — 开发规范文档

## 1. 规范概述

本文档定义IBM i项目文档规范的开发标准，包括代码规范、文档规范和流程规范。

## 2. 代码开发规范

### 2.1 通用代码规则（所有代码开发Agent）

| # | 规则 | 约束 |
|---|------|------|
| 1 | 禁止伪代码 | 不得使用伪代码实现 |
| 2 | 禁止假设性代码 | 不得使用假设性代码实现 |
| 3 | 禁止 mock | 不得使用 mock 代码实现（测试代码除外） |
| 4 | 生产环境标准 | 严格按生产环境开发 |
| 5 | Git 提交规范 | 遵循 Conventional Commits：`type(scope): description` |

### 2.2 IBM i开发规则

| # | 规则 | 约束 |
|---|------|------|
| 1 | 自由格式 | RPG 必须使用 **FREE 自由格式（维护旧代码除外） |
| 2 | 错误处理 | 文件操作必须包含错误处理（RPG: Monitor/On-Error；CL: MONMSG） |
| 3 | DDS 规范 | 字段名 ≤10 字符；PF 必须有键；DSPF 使用消息子文件 |
| 4 | 库名规范 | 禁止硬编码库名，使用 `*LIBL` 或 `RTVJOBA` 获取当前库 |
| 5 | 连接验证 | 开发前通过 SSH 验证服务器连接，确认库名和源文件可访问 |
| 6 | 代码探索 | 必须先 SSH 探索现有代码（列成员/读源码/查字段定义），保证风格一致 |
| 7 | ASP 路径 | 使用 ASP Group(IASP) 时，IFS 路径加 ASP 前缀：`/{ASP}/QSYS.LIB/...` |

## 4. 流程规范

### 4.1 工作流阶段

| 阶段 | 负责Agent | 产出物 |
|------|----------|--------|
| 提示词增强 | 提示词工程师 | 结构化请求 |
| 结果先行定义 | PM Agent | 结果蓝图 |
| 计划拆分 | PM Agent | 设计文档+子计划 |
| 覆盖核查 | 核查Agent | 核查报告 |
| 子计划执行 | PM Agent | 代码/配置 |
| 子计划核查 | 核查Agent | 核查报告 |
| 终态校验 | 核查Agent | 校验报告 |
| 合规稽查 | 稽查Agent | 稽查报告 |

### 4.2 子计划执行规范

| # | 规则 | 约束 |
|---|------|------|
| 1 | 独立文件 | 每个子计划一个独立文件 |
| 2 | 完整设计 | 子计划必须包含完整设计内容 |
| 3 | 无跳转 | 禁止使用"详见蓝图"等跳转词 |
| 4 | 逐字拷贝 | 结果蓝图内容必须逐字拷贝到子计划 |
| 5 | 执行不读蓝图 | 子计划执行阶段以子计划文件为准 |

### 4.3 Git提交规范

| 规则项 | 说明 |
|--------|------|
| 提交信息格式 | 遵循 Conventional Commits：`类型(范围): 描述` |
| 提交时机 | 每次回复结束后自动执行 |
| 提交操作 | `git add . && git commit -m "类型(范围): 描述"` |

## 5. 质量保证规范

### 5.1 自检清单

| # | 检查项 | 适用阶段 |
|---|--------|---------|
| 1 | 提示词增强是否已执行 | 所有阶段 |
| 2 | 阶段模板已完整输出 | 所有阶段 |
| 3 | 模板内容已保存到对应文件 | 所有阶段 |
| 4 | workflow-status.md 已更新 | 所有阶段 |
| 5 | Git 已提交 | 所有阶段 |
| 6 | 进入阶段前将模板所有产出物拆解为 todo 列表并逐项勾选 | 计划拆分 |
| 7 | 模板中每一项产出物都已实际生成 | 计划拆分 |

### 5.2 核查清单

| # | 检查项 | 适用阶段 |
|---|--------|---------|
| 1 | 蓝图→子计划覆盖核查 | 覆盖核查 |
| 2 | 子计划→产出逐行核查 | 子计划核查 |
| 3 | 蓝图→子计划全面覆盖检查 | 终态校验 |
| 4 | 合规检查 | 合规稽查 |
