# 用户请求记录：Agent 流程整改

## 原始请求

> 该项目是一个 agent 项目，接管我所有需求任务，自动调用相关 skill，切换合适的子agent完成任务，同时有吸取其他 agent skill 的能力，主要是从其他 agent 或 skill 项目中把对应的 agent、skill 吸收到当前 ai-team 的架构中。你作为一个 agent 资深设计工程师，你帮我看一下当前 agent 有什么流程不合理和有什么需要优化的地方。目的是使 agent 能够合理完成任务，不能随意发散，能自检所有 agent 的输出结果，保证交付质量。

## 模糊点确认结果

|------|--------|---------|

| 3 | 是否允许动"强制流程" | 允许 |

| 5 | 是否验证结论 | 需要 |

## 增强后的结构化请求

**项目背景**：`.ai-team/`（20 个 `agent.md`、34 个 `skill.md`、11 个规则文件）+ `AGENTS.md`（551 行，承载全部阶段模板）+ `agent-doc/`（产出物）。

**需求描述**：
1. 诊断当前 Agent 体系的流程缺陷，目标是"抑制发散、强制自检、保证交付质量"。
2. 诊断维度覆盖：入口断链、状态机可靠性、自检独立性、模板/规则冗余与冲突、Skill 调用机制、外部能力吸收、产出物落地一致性。
3. 每个问题给出证据（`文件:行号`）、影响、分级（P0/P1/P2）、修改建议。
4. 给出优化后的目标流程（关卡设置与用户确认点变化）。

**约束条件**：
- 技术：不引入外部框架依赖，改动限于 `AGENTS.md` / `.ai-team/` / `agent-doc/` 文档层。
- 质量：每条结论必须有仓库内可验证证据。
- 安全：不删除现有产出物内容；不提交密钥。

**期望输出**：评审报告（问题清单表 + 优先级 + 证据 + 建议 + 目标流程图），并落地整改修改。验收标准：结论可追溯到具体文件位置；每项建议写明"改哪个文件、改成什么"；覆盖三个目标。
